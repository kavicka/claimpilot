# ADR-009: AWS deployment with Terraform on ECS Fargate

Status: accepted, 2026-10-15

## Decision
Phase 2 runs in one AWS account in eu-central-1, described in Terraform (`infra/terraform`):

- ECS Fargate on ARM64 for all five services (ui, api, worker, core-mock, mcp). Service Connect
  gives them short names; only the load balancer is public, and only to `allowed_cidrs`.
- No NAT gateway. Private subnets have no route out of the VPC. Tasks reach Bedrock, ECR,
  CloudWatch Logs, Secrets Manager and X-Ray through VPC endpoints; the ADOT collector image comes
  through an ECR pull-through cache.
- RDS PostgreSQL 17 with pgvector, Valkey (ElastiCache) for the arq queue, EFS for uploaded
  documents and page renders. All are encrypted with one customer-managed KMS key.
- Uploads stay on a shared file system (EFS, mounted by the api and the worker through one access
  point), not S3.
- Secrets: RDS manages the database password; the application secrets (PII vault key, session
  secret, tokens) are generated by `scripts/deploy/secrets.sh` and written straight to Secrets
  Manager. Only the Valkey auth token is in Terraform state.
- `ha = false` by default: single-AZ database and cache, endpoints in one AZ. `ha = true` turns
  on the Multi-AZ versions.

## Why
- Terraform rather than CDK or CloudFormation: plain HCL is reviewable, `terraform test` with
  mocked providers checks the security properties without an AWS account, and tflint and checkov
  cover it in CI.
- Fargate rather than EKS or EC2: five small services and one CPU-heavy worker do not need a
  cluster to manage. ARM64 costs about 20 % less in Frankfurt and matches the Mac the images are
  built on.
- No NAT: a claim's content can only leave the VPC towards the services that have an endpoint.
  It also removes the NAT gateway's hourly and per-GB charges. The price is that every model the
  worker needs must be in its image (`claimpilot-prefetch` runs at build time, and the task runs
  with `HF_HUB_OFFLINE=1`).
- EFS rather than S3 for uploads: the api and the worker share files by path today
  (`storage_dir`). EFS keeps that code unchanged between the laptop and AWS. An S3 storage
  backend is the better long-term fit (lifecycle rules, object lock) and is listed as a follow-up.
- The PII vault key never enters Terraform state, so read access to state does not let anyone
  decrypt the vault.

## Consequences
- `make infra-check` (fmt, validate, mocked `terraform test`, tflint, checkov) runs without AWS.
  checkov reports 0 failed checks; each skipped check names its reason next to the resource.
- `make deploy` goes from an empty account to a running stack (`docs/deploy.md`); `make destroy`
  removes it and keeps a final database snapshot.
- Nothing here has been applied yet: no AWS account was used. The first `apply` is the first
  real test of IAM policies and endpoint routing.
- In the single-AZ demo, an AZ outage takes the app down until the AZ returns.
